# CRM-дашборд «Аналитика сделок»

Web-приложение на платформе VibeCode (Битрикс24), которое встраивается в портал и показывает
аналитику по сделкам CRM: воронку по стадиям, ключевые показатели и список последних сделок.
Данные берутся из подключённого портала Битрикс24 через REST-прокси (ключ `BITRIX_API_KEY`
из окружения приложения); приложение работает от лица авторизованного пользователя портала.

## Назначение и реализованные сценарии

Дашборд собирает и показывает три блока:

1. **Сводка по стадиям воронки** — количество сделок и их сумма по каждой `stageId`
   (горизонтальные бары с названием стадии, количеством и суммой; выигранные и проваленные
   стадии выделены цветом).
2. **Ключевые показатели (KPI)**:
   - общая сумма открытых сделок за период (сделки в работе, stageSemanticId `P`);
   - количество выигранных сделок за выбранный период (stageSemanticId `S`, по дате закрытия);
   - средний чек выигранных сделок за период.
3. **Последние сделки** — до 15 сделок за период: название, сумма, стадия и ответственный
   (имя подтягивается из справочника пользователей), с переходом в карточку сделки портала.

**Фильтр по периоду** — пресеты («Всё время», 7/30/90 дней, «Этот месяц») и произвольный
интервал «с/по» с валидацией дат. Фильтр применяется к каждой порции данных и корректно
обрабатывается на сервере: границы периода валидируются (`YYYY-MM-DD`), любые данные портала
читаются в фоне и кешируются по ключу периода, страница отдаётся мгновенно.

## Архитектура и запрошенные скоупы

Приложение — Node-сервер без внешних зависимостей (только стандартная библиотека) +
статический фронтенд (`public/`). Ключ `BITRIX_API_KEY` живёт только на сервере и не попадает
в браузер; браузер ходит на собственные `/api/*`.

Запрошенные права ключа и обоснование:

- `crm` — чтение сделок (`/deals/aggregate`, `/deals/search`) — обязательное право для всей
  аналитики;
- `user` — чтение текущего пользователя (`/users/me`) для приветствия и справочника
  пользователей (`/users`) для имён ответственных по сделкам.

Только чтение (`GET`/`/search`/`/aggregate`) — приложение ничего не пишет в CRM.

## Известные ограничения

- Долгие портальные вызовы (десятки секунд) — норма для прокси: дашборд собирает данные в
  фоне и отдаёт их из кеша, помечая возраст снимка («обновлено N мин назад»).
- На очень больших порталах агрегация по всему периоду может быть усечена порталом
  (`meta.truncated` / `OPERATION_TIME_LIMIT`), а период «Всё время» без фильтра по дате на
  портале с более чем ~5000 сделок возвращает `AGGREGATION_LIMIT_EXCEEDED`: дашборд честно
  показывает подсказку выбрать более короткий период, а не рисует неполную цифру как точную.
  По умолчанию приложение открывается за последние 30 дней — агрегация с фильтром по дате
  проходит на любом портале.
- Суммы KPI суммируются по полю `amount` в исходной валюте сделок и отображаются как рублёвые —
  на мультивалютных порталах возможна разнородность; карточка сделки показывает валюту из поля.
- Ссылки на карточку сделки строятся по `BITRIX_PORTAL_DOMAIN`; без него сделка показывается
  без ссылки.

## Инструкция для проверяющего

1. **Запуск локально**: `npm start` (или `node server.js`). Сервер слушает
   `process.env.PORT || 3000`, читает `BITRIX_API_KEY`/`BITRIX_API_BASE_URL`/`BITRIX_PORTAL_DOMAIN`
   из `.env` (ищется вверх от `server.js`) или из окружения.
2. **Проверка состояния**: `GET /api/health` — наличие ключа, справочники, снимки.
3. **Данные**: `GET /api/dashboard?preset=all|7d|30d|90d|this_month` или
   `?preset=custom&from=YYYY-MM-DD&to=YYYY-MM-DD`. При первом обращении возможен ответ `202`
   (данные собираются) — повторить через несколько секунд.
4. **Развёртывание**: опубликовать проект в VibeCode кнопкой «Деплой» в карточке «Приложение»
   (или через `vibecode_deploy`). Приложение откроется по адресу `https://app-<id>.vibecode.bitrix24.tech`.
   Ключ должен иметь права `crm` и `user`.
5. **Встройка в портал**: в кабинете Вайбкода встроить приложение как пункт левого меню
   (или вкладку), указав адрес опубликованного приложения — привязку выполняет само приложение
   через OAuth-токен, а не входящий вебхук.

## Проверка безопасности

Перед публикацией код прошёл проверку безопасности (режим predeploy скила `security-check`):
защита от path traversal при отдаче статики, строгая валидация периода, рендеринг данных через
`textContent` (защита от XSS), ключ приложения — только на сервере и только из окружения.
